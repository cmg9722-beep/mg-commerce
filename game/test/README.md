# 검증 스위트

```bash
node game/test/run.mjs              # 전부
node game/test/run.mjs i18n play    # 이름에 맞는 것만
RUNS=8 node game/test/run.mjs random
```

`CLAUDE.md`의 배포 전 체크리스트 2·3번(변경 기능 테스트 · 회귀 테스트)을
사람 손 대신 여기서 돌린다. **전부 ✅ 여야 push 한다.**

브라우저는 이미 설치된 Chromium을 쓴다(`/opt/pw-browsers/chromium`).
게임이 파일 한 개라 `file://`로 바로 열고, 서버는 필요 없다.

`play`·`random`은 `lib.mjs`의 `autoplay()`를 같이 쓴다. 게임 시간만
3배로 돌리고(`window.__fast`) 키 입력과 판정은 그대로다 — 실시간으로
다 돌리면 한 판에 10분이 넘어서 아무도 안 돌린다.

## 검사를 쓸 때 지키는 것

**`g.P.x`를 직접 옮기지 않는다.** 이동 규칙·충돌·입력 처리를 건너뛴
검증은 「검증했는데 깨졌다」로 돌아온다. 조작을 봐야 하면 `play`처럼
`p.keyboard.down('KeyW')`를 쓴다.

**검사가 틀렸을 가능성을 먼저 의심한다.** 지금까지 ❌ 셋 중 둘이 검사 탓이었다.
- 야근이 「무효과」로 잡혔다 → 검사가 적을 Lv1 반경(75px) 밖인 90~200px에 놓았다
- 언어 선택 단추 「한국어」가 「번역 누락」으로 잡혔다 → 그건 일부러 한국어다
- 무작위 판이 「1구역에서 안 나감」으로 잡혔다 → 검사가 플레이어를 안 움직였다

**구문이 맞다고 자리가 맞는 건 아니다.** 서비스워커 등록이 직군 클릭 핸들러
안에 파묻힌 적이 있다. `renderStart()` 의 첫 번째 등장을 바꾼 탓인데,
JS로도 멀쩡하고 화면도 멀쩡해서 열한 개 검사가 전부 통과했다.
그래서 `offline` 검사가 이제 **진짜 http 서버로 띄워** 등록을 확인한다 —
file:// 로는 서비스워커가 아예 등록되지 않아 이 버그를 볼 수가 없었다.

반대로 검사가 진짜를 잡은 적도 있다. 직군 선택이 저장되지 않던 건
`loadSave()`의 화이트리스트에서 한 줄이 빠진 탓이었고, 눈으로는
「됐네」로 보였다 — 고르면 바로 반영되고, 다음 날에만 사라졌으니까.

❌가 뜨면 게임을 고치기 전에 검사를 먼저 읽는다.

**스토어에 내는 말은 검사로 지킨다.** 방침에 「수집하지 않는다」고 써 놓고
코드가 수집하면 그건 거짓 신고다. `store` 검사가 광고·분석 SDK와 저장 키를
코드에서 직접 읽어 방침과 대조한다. 저장 키를 새로 만들면 방침에도 적어야
검사가 통과한다.

**새 기능에는 검사를 같이 낸다.** 기능만 넣고 넘어가면, 그 기능이
언제 깨졌는지 아무도 모른다.
