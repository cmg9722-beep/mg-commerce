# 사무실 방어 — 출근 저지

복도로 걸어오는 상사를 내 자리 앞에서 막는 **레인 디펜스**.

## 실행

의존성·빌드·서버 없음. `game/index.html` 을 브라우저로 열면 끝.
MG Commerce Flask 앱과 완전히 분리되어 있어 배포에 영향 없음.

## 왜 레인 디펜스인가

초기 프로토타입(카드로 지연을 누적시키는 방식)은 플레이어가 할 일이 5번 클릭뿐이고
나머지는 타이머를 구경하는 구조였다. 게임이 아니라 계산기에 가까웠다.

레인 디펜스는 **재미가 이미 검증된 장르 구조**이고, "다가오는 것을 막는다"는
저지 컨셉과 정확히 맞아떨어지며, 무엇보다 플레이 내내 손이 바쁘다.

장르 문법만 차용했고 코드·그래픽·고유명사는 전부 자체 설계다.
(기획 메모 7-3 "게임 복제에 대한 정확한 선" 참조)

## 규칙

- 필드는 5줄 × 9칸. 적은 **오른쪽에서 왼쪽**으로 걸어온다.
- 맨 왼쪽 파란 칸이 **내 자리**. 한 명이라도 도달하면 패배.
- 자원은 **커피**. 시간이 지나면 조금씩 들어오고, 정수기를 세우면 빨라진다.
- 사물을 고르고 복도 칸을 클릭해 설치한다. 모든 웨이브를 막아내면 클리어.

## 설치 사물

| 사물 | 비용 | HP | 기능 |
|---|---|---|---|
| 💧 정수기 | 50 | 60 | 5초마다 커피 +25 |
| 🧱 파티션 | 50 | 520 | 공격 없음 — 때리는 동안 시간을 번다 |
| 🖨️ 복사기 | 100 | 110 | 1.4초마다 서류 발사 (22) |
| 📎 스테이플러 | 175 | 110 | 0.55초마다 연사 (14) |
| 📄 사직서 | 125 | — | 설치 즉시 그 줄 전체에 420 피해 |

## 적

직급이 **체격**(HP·속도), 부서가 **능력**이다. 둘은 따로 붙는다.

### 직급

| 적 | HP | 속도 | 공격 |
|---|---|---|---|
| 인턴 | 70 | 26 | 8 |
| 사원 | 140 | 20 | 11 |
| 대리 | 230 | 17 | 13 |
| 과장 | 280 | 27 | 15 |
| 부장 | 620 | 12 | 22 |
| 회식조 | 180 | 30 | 12 |
| **점검단** | **1500** | 10 | 34 |
| 파렛트 / 불량품 / **납품차** | 200 / 90 / **1300** | 22 / 34 / 11 | 10 / 15 / 30 |
| 재고차이 / 세금계산서 / 미수금 | 260 / 110 / 190 | 15 / 30 / 20 | 8 / 10 / 12 |

### 부서

웨이브 항목에 부서를 붙이면(`[t, 줄, 직급, 부서]`) 같은 직급이 전혀 다르게 행동한다.
좀비는 내 경제를 건드리지 않고 내 사물을 뺏어가지 않는다 — 부서는 그걸 한다.

| 부서 | HP× | 속도× | 능력 |
|---|---|---|---|
| 영업 | 0.85 | 1.30 | **벽 뒤에서 나온다** — 복도 중간(x=FW×0.55)에 기습 스폰 |
| 생산 | 1.55 | 0.80 | 물량. 두껍고 느리다 |
| 품질 | 1.00 | 0.90 | **점검** — 앞의 사물이 발사 정지. 사물 피해는 30%만 |
| 재무 | 0.90 | 1.00 | **예산 삭감** — 전진하는 동안 커피 초당 −9 |
| 인사 | 1.15 | 0.95 | **차출** — 사물을 부수지 않고 제거, 자기 체급의 30% 회복 |

직급 5 × 부서 5 = 25종이 테이블 두 개에서 나온다.
화면에서는 **부서 배지 + 부서색 HP바 + 부서 소품**(안전모·클립보드·계산기·서류철·서류가방)으로 구분된다.
부서가 나오는 스테이지는 브리핑에서 등장 부서를 순서대로 설명한다 — 죽고 나서 배우게 하지 않는다.

## 스테이지

| 스테이지 | 성격 | 묻는 것 |
|---|---|---|
| 출근 저지 | 기본. 사원·대리 중심에서 부장 러시로 마감 | 화력을 **어떤 순서로** 세울까 |
| 점심시간 외주납품 | 전 줄 동시 입고 → 소강 → 또 입고 | 전선을 **얼마나 넓게** 펼까 |
| 회식 저지 | 회식조가 빠르고 수가 많다 | **속도**를 어떻게 감당할까 |
| 주간 업무보고 | 다섯 부서가 교대로, 마지막엔 합동 | **뒤(왼쪽)** 를 어떻게 지킬까 |
| 반품 처리 | 물량은 적다. 처리한 것의 절반이 되돌아온다 | **끝난 게 끝난 게 아닐 때** |
| 월말 마감 | **승리 조건 반전** (아래) | **막을까, 처리할까** |
| 고객사 점검 | 보스전. 점검단 3명(HP 1500) | 보스에 화력을 **어떻게 집중**할까 |

### 반품 처리 — 처리한 적이 되돌아온다 (`returns`)

```js
returns:{ rate:.5, hp:.5, spd:1.5 }   // 처치 2건당 1건이 되돌아온다
```

- **난수를 쓰지 않는다.** 누산 방식(`retAcc += rate`)이라 "절반"이 정확히 절반이다.
  플레이어가 다음에 뭐가 올지 배울 수 있어야 한다.
- 되돌아온 적은 체력 절반, 속도 1.5배. **반품은 한 번만** — 무한 루프가 없다.
- 보스는 반품되지 않는다.
- 필드에서 붉은 점선 테두리 + 「반품」(학생 팩 「재시험」) 태그로 표시된다.
- 스폰 물량 자체는 다른 스테이지보다 적다. 반품이 실질 물량을 두 배로 만든다.

### 월말 마감 — 승리 조건이 반전되는 스테이지 (`mode:"closing"`)

- 승리 조건이 생존이 아니라 **처리 건수**. 마감 시각 100초까지 40건.
- 적이 자리에 도달해도 **지지 않는다.** 죽지 않고 「미처리」로 남는다.
  미처리가 허용치 6건을 넘으면 그때 마감 실패.
- 마감 D-22초부터 **가산세 압박** — 적 속도 ×1.4, 화면이 붉어진다.
- HUD가 웨이브 진행바 대신 마감 시계 + 처리/목표 + 미처리/허용을 보여준다.

## 테마 팩

같은 엔진 위에 데이터만 갈아끼운다 (`usePack(id)`).

| | 직장인 팩 | 학생 팩 |
|---|---|---|
| 자원 | 커피 | 매점 포인트 |
| 내 자리 | 내 자리 | 내 책상 |
| 사물 | 정수기·파티션·복사기·스테이플러·사직서 | 자판기·사물함·자습서·필통·조퇴증 |
| 부서 | 영업·생산·품질·재무·인사 | 체육·수학·과학·영어·음악 |
| 보스키(ESC) | 생산실적 집계 | 중간고사 오답노트 |

학생 팩의 적은 **전부 사물**이다. 선생님도 학생도 그리지 않는다 —
아이와 학부모가 보는 물건이라 여기는 타협하지 않았다.

학생 팩 스테이지는 오피스 팩의 **검증된 웨이브 표를 그대로 쓰고**
적 종류만 치환한다(`reskin` + `KMAP`). 밸런스가 갈라지지 않는다.

## 검증 (Chromium 실측)

전부 Playwright + Chromium 헤드리스로 **실제 플레이**해서 측정한 값이다.

### 스테이지 완주 (두 팩 × 6스테이지)

| 스테이지 | 5줄 방어 | 3줄 방어 | 무방비 |
|---|---|---|---|
| 출근 저지 | 성공 20처리 124초 | — | 함락 |
| 점심시간 외주납품 | 성공 36처리 129초 | 함락 43초 | 함락 43초 |
| 회식 저지 | 성공 26처리 108초 | — | 함락 |
| 주간 업무보고 | **왼쪽 무방비 → 함락 135초 / 왼쪽 화력 → 성공 133초** | 함락 78초 | 함락 60초 |
| 반품 처리 | 성공 39처리(스폰 26 + 반품 13) 125초 | 함락 69초 | 함락 50초 |
| 월말 마감 | 완료 42/40, 미처리 0, 83초 | 실패 26/40, 미처리 7 | 실패 0/40, 미처리 7 |
| 고객사 점검 | 성공 23처리 150초 | — | 함락 |

주간 업무보고는 **앞 스테이지들의 최적 빌드로 클리어되지 않는다.**
영업 부서가 벽 뒤에서 나오기 때문에 왼쪽에 화력을 두는 빌드가 따로 필요하다.

### 부서 능력 개별 계측

| 부서 | 측정 |
|---|---|
| 재무 | 커피 1000 → 990 (전진 1.2초) |
| 품질 | 접촉한 사물의 `stun` 활성, 발사 정지 확인 |
| 인사 | 사물 5개 → 4개, 적 HP 100 → 268 (차출 + 회복) |
| 영업 | 스폰 x=426 (화면 끝 774) — 복도 중간 |

### 반품 규칙 개별 계측

| 항목 | 측정 |
|---|---|
| 비율 | 20건 처치 → 정확히 10건 반품 (난수 아님) |
| 체력 | 140 → 70 |
| 속도 | 20 → 30 |
| 재반품 | 반품된 10건을 재처치 → 재반품 0건 |

### 그 외

- 적 스프라이트 커버리지 26/26, 이모지 폴백 잔여 0
- 부서 소품 5직급 × 5부서 = 25칸 전부 실제 게임 코드로 렌더 확인 (양쪽 팩)
- 마감 가산세 구간: D-20에서 `crunch` 클래스 활성, 적 속도 배수 1.4, 미처리 카운트 정상
- 음소거 토글/M키 왕복, localStorage 유지 확인
- 보스키(ESC) 팩별 분기 확인
- **JS 콘솔 에러 0건**

### 수정한 실제 버그

1. **탄 관통(터널링)** — 프레임이 길어지면 서류가 적을 뛰어넘어 아무도 죽지 않던 문제.
   스윕 판정(이전 위치~현재 위치 구간 검사)으로 수정.
2. **접촉 판정** — 적이 유닛이 있는 칸에 들어서는 순간 칸 끝에서 멈추던 문제.
   기준점을 20px 앞으로 옮겨 자연스럽게 접근하도록 수정.
3. **초반 무방비 구간** — 시작 커피가 정수기 3개 값밖에 안 돼 첫 웨이브를 맨몸으로 맞던 문제.
   시작 자원 상향 + 첫 웨이브를 뒤로 이동.
4. **게임 루프가 안 멈춤** — 게임 화면을 떠나도 rAF 루프가 계속 돌았다.
   게임 도중 나가서 팩을 바꾸면 옛 grid를 새 UNITS/FOES 테이블로 그리다 TypeError로 죽었다.
   `stopLoop()` + 화면 전환 시 루프 정지 + 루프 자체의 `SCREEN` 확인으로 이중 방어.
5. **사운드 래퍼 누락** — `S()` 호출부 13곳이 배선됐는데 정의가 없어 팩 선택에서 즉사.
6. **밸런스: 인사 차출이 사실상 무적** — 뺏은 사물 기준 60%를 회복해서
   파티션(520HP) 하나 먹은 사원이 312를 회복했다. 자기 체급 30%로 변경.
7. **밸런스: 가산세 구간이 발동을 안 함** — 마감 목표가 34건일 때 잘하는 플레이어가
   74초에 끝나 D-22 구간에 도달조차 못 했다. 규칙이 있으나 마나였다. 목표를 40으로 상향.

## 아트

`../design/` 의 채택 방향 **「형광등 꺼진 사무실」** 적용 완료.
필드의 유닛·적·의자, 팔레트 카드 아이콘, 부서 소품까지 전부 **인라인 Canvas2D 벡터**다 (이모지 아님).
모든 스프라이트는 `(ctx, cx, cy, s)` 시그니처를 공유한다 — `cx,cy`가 중심, `s`가 정사각 박스 한 변.

| 전역 | 내용 |
|---|---|
| `SPRITES` | 직장인 팩 유닛·적·의자 |
| `SPRITES_SCHOOL` | 학생 팩 유닛·적·책상 |
| `SPRITES_LUNCH` | 점심 스테이지 적 6종 (양 팩) — 각 팩 `foes`에 병합됨 |
| `SPRITES_CLOSING` | 마감 스테이지 적 6종 (양 팩) — 각 팩 `foes`에 병합됨 |
| `SPRITES_DEPT` | 부서 소품 10종 — 직급 스프라이트 **위에 덧그린다** |

부서 소품이 오버레이인 덕에 소품 5개로 5직급 × 5부서 = 25종을 커버한다.

스테이지 선택 화면의 아이콘만 아직 이모지 — 인게임이 아니라 후순위로 두었다.
