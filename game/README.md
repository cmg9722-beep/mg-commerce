# 정시 퇴근

09:00에 출근해 **18:00 전에 회사 건물 아홉 구역을 뚫고 정문으로** 나가는
생존형 액션(뱀서라이크).

```bash
node game/test/run.mjs      # 검사 전부. 통과해야 push (CLAUDE.md)
```

파일 하나다. `game/rush.html` 을 브라우저로 열면 끝 — 의존성도 빌드도
서버도 없다. 글꼴·소리·그림까지 안에 들어 있어 비행기에서도 열린다.
운영 중인 주소는 `/game/` (`app.py` 가 서빙).

> 같은 폴더의 `index.html` 은 **다른 게임**(레인 디펜스 「출근 저지」)이다.
> 문서는 `README.defense.md`.

## 왜 이 장르인가

「정시에 못 나간다」는 한국 직장인이 매일 겪는 일이고, 그게 게임의 승리
조건이 되면 규칙이 저절로 이야기가 된다. 점수가 아니라 **퇴근 시각**이
결과다 — "13:25. 정시보다 4시간 35분 일찍입니다."

장르 문법만 차용했고 코드·그래픽·고유명사는 전부 자체 설계다.
등장 인물·부서는 전부 가상이다(아래 「선」 참조).

## 구조

| 층 | 무엇 |
|---|---|
| **구역** 9개 | 지하 주차장 → 로비 → 사무실 → 구내식당 → 소회의실 복도 → 대회의실 → 탕비실 → 임원층 → 대표이사실. 구역 몫을 끝내야 문이 열린다 |
| **구역 규칙** 7종 | 점심시간엔 진도가 멈추고, 발표는 자리에 서야 하고, 조용한 층은 몰아칠수록 더 온다 |
| **무기** 33종 | 기본 21 + 진화 12. 여섯 칸 |
| **태그·반응** | 젖음·묶임·참조·서류 → 번짐·지적·전달 |
| **직군** 5종 | 능력치 + 전용 특성(반응 성향) + 3승 시 두 번째 시작 무기 |
| **직급** 7단계 | 천장(`SAVE.rank`)과 오늘 출근하는 자리(`rankPick`)가 따로 |
| **이야기** 30일 | 나 하나가 나가는 이야기 → 규정이 되는 이야기 |
| **오늘의 공지** | 날짜가 그날 사건 계획표를 정한다. 서버·계정 없이 |
| **야근 엔드리스** | 정문에서 「오늘은 안 나간다」. 바퀴마다 적 +35%, 보상 +55% |
| **런 시드** | 결과 화면 여섯 자 코드. 로비에 넣으면 같은 하루 |

## 코드 지도 (`rush.html`)

한 파일이지만 순서가 있다.

| 대략 | 무엇 |
|---|---|
| ~1400 | 소리(WebAudio 합성) — `Math.random` 을 쓴다, 판과 무관 |
| ~3270 | `clamp`, **`rnd()`/`seedRun()`** — 판의 난수는 여기서 갈린다 |
| ~3300 | 번역표 `L10N` |
| ~3700 | 시계(`DAY`·`H0`·`H1`·`clockStr`), 직급, 구역 `ZONES` |
| ~4000 | 사건 `RND`, **오늘의 공지**(`dailyPlan`·`dayKey`) |
| ~4280 | 무기 `WEAPONS`, 진화 `EVO`/`EVOLVED`, 강화 `PERKS`, 직군 전용 `CHAR_PERKS` |
| ~4600 | 적 `E`, 대사 `SAY`, 체형 `BODY` |
| ~4800 | `newGame`, `stats`, `applyPerks`, 스폰 `spawnRing`/`spawnWall`/… |
| ~5200 | `nextZone`, 문 `openGate`, **정문 선택 `askLoop`** |
| ~5700 | **`damage()` — 모든 무기의 단일 관문. 반응이 여기서 난다** |
| ~5900 | `killFoe`(전달 반응), `step` |
| ~7400 | 그리기 `drawWorld` — `Math.random`(화면 흔들림), 판과 무관해야 한다 |
| ~7800 | 카드 `offers`, 업적 `ACH`, 목표 `GOALS` |
| ~8100 | 화면들 — 로비 `renderStart`, 기록, **도감 `renderCodex`**, 상점, 결과 `renderEnd` |
| ~8600 | 입력, 부팅, 검사 훅(`window.__api` 등) |

### 반드시 알아야 할 것 둘

**`damage()` 는 모든 무기의 단일 관문이다.** 태그 부여와 반응 셋이 전부
거기서 난다. 무기를 더할 때 반응을 따로 짜지 마라 — 소스 id(`src`)만
넘기면 된다. 거기서 사고가 나면 전부에 난다(순회 중 `splice` 로 한 번
당했다).

**판의 난수는 `rnd()` 다.** 시각·소리·로비는 `Math.random` 이다. 이 경계가
무너지면 같은 시드가 다른 판이 되고, 밸런스를 잴 수 없게 된다. 실제로
그리기가 난수를 먹어서 측정이 세 번 무효가 됐다. `determinism`·`seed`
검사가 이걸 지킨다.

## 검사

`game/test/README.md` 에 무엇을 보는지와 지금까지 잡은 사고들이 있다.
**전부 ✅ 여야 push 한다.** 밸런스를 건드리기 전에는
`node game/test/run.mjs determinism` 을 먼저 돌려라 — ❌ 면 그날 잰
숫자는 전부 버려야 한다.

`rush.html` 을 고치면 `sw.js` 의 `CACHE` 해시를 갱신한다. 안 하면 고친
것이 이미 설치한 사람에게 영영 안 간다. `offline` 검사가 바꿔야 할
문자열까지 찍어 준다.

## 선

- 등장 인물·부서는 전부 가상. **실존 인물·거래처명 사용 금지.**
- 이 규칙은 **리스킨(다른 회사 이름을 단 판본)에도 그대로 적용된다.**
  마지막 보스가 대표이사인 게임에 실제 회사 이름을 달면 그 회사의 대표
  한 사람이 특정된다. 발주사가 서면으로 원해도 마찬가지다 — 회사의 동의는
  묘사되는 개인의 동의가 아니다. 그래서:
    · 실명·실직책이 특정되는 인물은 **본인 서면 동의**가 따로 필요하고,
      없으면 역할명만 쓴다(대표이사·본부장·인사팀 — 지금 그대로).
    · 직원 이름·사진은 어떤 경우에도 안 넣는다. 부서명·구역명·사내 은어까지가 선.
    · 노조·단체교섭 콘텐츠는 팩에서 끌 수 있어야 한다. 인사팀이 발주하는
      순간 그게 문제가 된다 — 지우는 게 아니라 발주사가 고르게 한다.
    · 회사 이름이 든 빌드는 스토어에 올리지 않는다(상표·연령등급 재신고).
      발주사 도메인 URL 또는 파일 전달로만, 배포 책임은 발주사에.
  영업용 데모는 **가상의 회사**로 만든다.
- 바깥으로 아무것도 보내지 않는다. 저장은 브라우저 안 `localStorage`
  한 칸뿐이고, 그 내용은 `store/PRIVACY.*` 에 그대로 적혀 있다.
  `store` 검사가 방침과 코드를 대조한다 — 저장 키를 늘리면 방침도 고쳐야
  통과한다.
